## Live contract and ordering

Canonical issue: https://github.com/redrossa/neomd/issues/15. Read its complete body and all four comments through GitHub REST, including the D1/D2 approvals. All seven body checkboxes are unchecked:

1. Hide HTML comments from both the page and accessibility reading order.
2. Escaped punctuation appears literally without its escape character.
3. Markdown examples inside code remain literal, even when they contain headings, links, or comments.
4. Do not provide a raw-source mode or require source inspection to recover from a problem.
5. Treat incomplete or unsupported syntax as best-effort readable content; preserve text rather than silently discarding it. Intentional literal syntax can still appear as document content.
6. Render supported HTML formatting without executing embedded scripts or allowing document content to replace the app's UI.
7. Render document-leading YAML front matter as a readable metadata table, like GitHub, rather than hiding it or displaying raw YAML delimiters and source.

The story statement is: “As a nontechnical reader, I want formatting instructions to stay out of the reading experience so that the document feels finished.”

### D2 — Approved scalar/empty delimiter precedence and recovery default

**Approved:** recognize a front-matter envelope ONLY at document start, after at most one BOM, opening physical line `---` (column zero; optional trailing ASCII spaces/tabs), terminated by the first corresponding column-zero `---` or `...` line (same trailing-whitespace allowance). LF, CRLF and CR work. No leading blank/comment/preamble, indentation, `+++`, braces-only format, later in-document envelope, code-fence or quoted/list envelope recognition. Do not hide arbitrary leading content until a closing delimiter appears.

Within a closed envelope accept YAML root mappings, sequences AND scalars; nested/flow/block/multiline values are supported. An empty envelope is an empty metadata table state, not thematic rules. **This necessarily means `---\nHello\n---` is scalar metadata, and `---\n---` is empty metadata, even though an author could intend Markdown rules/setext structure.** There is no parser trick that can infer intent. The user approved conventional front-matter-at-start precedence, including these two examples; do not narrow to mappings or ordinary-Markdown precedence.

No closing delimiter: leave the whole input to the existing Markdown parser (no YAML consumption or missing-body error). Closed but malformed/over-budget data: show the full candidate as a read-only literal fallback with a quiet “Metadata couldn’t be formatted; its text is shown below” explanation, followed by normally rendered body. Do not require source mode; do not discard candidate data. These invalid/unsupported fallbacks are C5 behavior, not a claim of a valid C7 table. If a candidate exceeds parse budget, still find the envelope/body boundary by linear line scan; do not send the oversize candidate through a general YAML object loader. The fallback must not turn into app UI, links, images or parsed Markdown headings.

Both required gates are resolved by the linked approvals. The following limits, row representation and file split are concrete engineering choices implementing that contract, not new product scope. Worker must report necessary corrections without treating a parse failure as successful table rendering.

## Safe YAML implementation semantics

- **Mapping / sequence / scalar / empty:** native key/value table; ordered nested descendants rendered with full key/index context and visible hierarchy, not YAML delimiter/source text. Top-level sequence has numbered item context; scalar has a “Value” row. Empty document/mapping/sequence and empty strings have explicit readable empty-state labels (distinguish empty string from empty mapping/sequence). No fixed flat-only restriction.
- **Scalar display:** use libyaml's decoded scalar value, respecting YAML quoted escaping and folded/literal multiline semantics. Plain `2025-01-29`, `001`, `yes`, booleans and numerals remain their decoded textual spelling rather than Foundation date/number locale conversions. Preserve mapping/sequence order. Plain null/empty values may have a descriptive “Empty value” presentation, while quoted empty strings say “Empty string”; do not reclassify arbitrary text with YAML 1.1 coercions. Scalar strings containing `**`, `:smile:`, `[link](…)`, HTML, backticks, or template syntax are metadata DATA, not Markdown instructions.
- **Keys and duplicates:** keep ordered mapping pairs, including non-scalar keys represented through their own nested structure/context. Do not force a dictionary keyed only by String or silently overwrite repeated keys. Duplicate authored keys can be displayed as separate rows (best-effort preservation), not silently merged. Never use recursive hash/equality over untrusted arbitrary nodes.
- **Anchors/aliases:** store alias edges, not expanded trees. Resolve known anchors according to event order; reuse/shadowed names bind to the appropriate existing definition. Validate referenced targets and track the current traversal path; undefined references/cycles return a readable whole-candidate fallback. Expand acyclic references for display only under shared total visit/output limits so exponential alias fans cannot produce exponential work. No resolver touches external files or network. Acyclic aliases are not silently excluded as “non-flat YAML.”
- **Tags:** retain explicit tag names as inert descriptive metadata along with underlying scalar/collection data; no custom constructors, object instantiation or tag-directed includes. For example a tagged scalar remains its text, not a URL fetch or executable. Standard type tags do not trigger Foundation conversion; explicit binary remains base64 text, not an attachment. Unsupported or invalid tag syntax causes readable fallback, not removal. Tags alone are not executable and need not exclude an otherwise readable tree.
- **Resource limits:** proposed named constants (engineering choices, not promised GitHub limits): parse envelope payload at most 256 KiB UTF-8, depth at most 64, at most 10,000 owned metadata nodes, at most 40,000 consumed events, at most 20,000 presentation node-visits and 1 MiB cumulative displayed scalar bytes including alias reuse. Enforce while receiving events / before appending output, not after recursively constructing values. Bound alias/name/mark storage by node/input limits. Abort/dispose cleanly on limits; preserve original candidate content in non-executing fallback. Per-event C scanner work/memory is bounded by the input cap, not by a fabricated hard real-time timeout. This is risk reduction, NOT proof against all C-library vulnerabilities. Worker must add non-interaction adversarial unit coverage for boundary and above-boundary cases.
- **No recursive destruction/view tree:** flat arena with indices, iterative assembly/validation/flattening; bounded table rows with plain attributed cell text. Do not reintroduce unbounded recursion into a renderer deliberately made stack-safe in M1-09.
- **Budget accounting details:** depth is the count of simultaneously open mapping/sequence containers (root collection = 1); node count includes scalars, collections and aliases; count every consumed event, including stream/document boundaries. Input cap applies to UTF-8 payload bytes between delimiter lines, including payload line endings. Equality to a cap is permitted, overflow fails before append. Validate the whole single YAML document through STREAM_END (one DOCUMENT_START/END); do not accept a successful prefix with malformed trailing payload. Count a presentation visit whenever a node is processed, including repeated alias targets and structured keys. Cap rows to at most the visit cap and account for cumulative key/path/index/tag labels and values in the 1 MiB output cap, not scalar bytes alone. Use index edges/context stacks rather than copying growing path strings per node. Check integer additions before allocating. Empty/tag/collection rows must be budgeted too. A parser/event error or incomplete mapping pair rolls back the entire formatted projection, not a partial table plus lost values.
- **Fallback data boundary:** retain the exact original candidate range including delimiter-line terminators and optional BOM as immutable source data; retain body separately, unchanged. A BOM may remain nonprinting. Literal fallback gets plain attributed text only, with no markdown parsing initializer, `.link`, `.markdownImage`, generated reference, color/emoji cue, HTML-style, or custom-anchor attributes. The quiet explanation is separate from original text. Never send fallback text through cmark, inlineHTML, picture handling, highlighting or autolink discovery. Preserve all original scalars/line endings in owned fallback data; native visual newline normalization is not a file rewrite. The metadata parse/output caps do not truncate fallback. Prefer a source slice/shared source storage, and a measured literal leaf with wrapping/normal scrolling; do not build a second huge YAML/Markdown tree. Extremely large fallback native layout responsiveness remains unverified, not promised bounded by the small YAML parse cap.

### Comment-token handling details

Keep cmark HTML-node boundaries until comment classification is complete. An `.inlineHTML` attributed run can coalesce several nodes or be split by inherited link/emphasis attributes; it is not a reliable original token. Use a leaf-scoped iterative token context during the actual inline AST walk, before constructing image alternative strings, link labels or attributed runs; carry the context across descendant nodes in source order. Code/text/entity-derived runs cannot open a comment merely because their decoded text spells `<!--`. Standalone true `html_inline` comment tokens can be dropped whole once their scanner-recognized complete terminator is known. A block HTML literal needs a linear tokenizer because it may contain several tags/comments/text suffixes. Recognize HTML comments' normal `-->` and `--!>` termination as appropriate to cmark HTML provenance, plus inline parser special complete `<!-->`/`<!--->`; retain unclosed constructs. Add exact cases rather than assuming a regex models all cmark token boundaries.

In data context, parse whole start/end tags with quoted-attribute state (both quote styles, `>` inside quotes) before looking for comment openers. Keep an opaque/raw-literal element context for script/style/textarea/title and the existing pre/code example-preservation policy; exit only on an actual matching case-insensitive end tag with a name boundary, not an apparent close in an attribute. Apparent comment spellings inside those literal regions remain readable, never executable. Inline raw-literal context must survive separate HTML and ordinary-text nodes in the same leaf; block context must cover its full literal. If a required literal context crosses separate HTML block leaves (e.g. blank-line-separated `<code>`), carry only the narrow tokenizer state across contiguous HTML content, not a global regex over the document or unrelated Markdown code. Invalid or undecidable tag constructs stay literal under C5. Do not erase an attribute value, decoded escape, code sample, metadata value or rawtext string as a comment.

Feed the surviving original eligible tag tokens to existing supported-wrapper matching with stable output scalar ranges; never rescan concatenated sanitized text as fresh HTML. For example, removing a comment between literal `<su` and `p>` must not manufacture a supported `<sup>` wrapper. Likewise removing a comment must not promote adjacent ordinary text into Markdown link/emoji/task/color syntax; cmark has already classified that text. Suppress comment-derived anchors, link-label/image-alt text and heading-slug contributions before allocation/materialization. Complete comment-only leaves disappear, except existing empty task/anchor carrier semantics. For picture blocks, only the pre-existing original narrow grammar gets image authority; sanitize otherwise literal HTML independently and do not use comment removal to broaden accepted picture content. These are source-level safeguards; worker must confirm precise cmark splits with non-interaction regression assertions, not a production parser rewrite.
