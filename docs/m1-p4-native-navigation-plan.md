# M1-P4 / #43 — revised native navigation design

Status: **Approved implementation design.** [Binding coordinator approval](https://github.com/redrossa/neomd/issues/43#issuecomment-5626782971) records the user's “1. yes, 2. yes”: Command-N uses a single-file picker and batches are rejected with one-file-at-a-time feedback. This supersedes the historical pending D1/D2 language and BLOCKED handoff. Research itself performed no prototype, build or interaction. Worker evidence is recorded separately; native behavior remains deferred/unverified.

Base: `9db15f86682dcd8c0c97290d541186c006d8f5bb`. Canonical issue: https://github.com/redrossa/neomd/issues/43. This document supersedes the unapproved options in the earlier triage, not existing acceptance evidence.

## Settled contract

- Embedded/native reading remains Markdown-only (`md`, `markdown`, `mdown`, `mkd`, `mdtext`, case-insensitive). Other safe local targets use default apps; applications/executables are revealed in Finder, never launched by the file dispatcher.
- Local document links, File > Open / Command-O and file drops replace the destination reader in its **existing NSWindow**. Command-click has ordinary activation semantics. Only Command-N explicitly requests an additional reader window.
- Disable App Sandbox **only for the app Debug and Release configurations**; remove enclosing-folder grants and image permission buttons. No persistent folder bookmarks, setup/management UI, grants, migration or helper process.
- Preserve read-only behavior, source bytes and modification times. No other security-control, signing/team/identifier/deployment change. Unsandboxed distribution is not Mac App Store compatible. macOS privacy controls, ACL/POSIX access and unavailable volumes can still deny reads or trigger system-owned prompts.
- Retain the last readable window, title, URL and reading state on failed/canceled/superseded replacement. Retain path/fragment semantics, explicit-only links, rendering, startup native picker and windowless last-close behavior.

## Smallest coherent native ownership boundary

Replace the document **scene shell**, not the rendering stack. Use an app-owned AppKit application/document/window layer and host the existing SwiftUI reader with `NSHostingController`. Do not keep a hidden DocumentGroup as a second owner, inspect private SwiftUI controllers, open-then-close windows, mutate an existing document's `fileURL` to fake navigation, or implement browser/history/tab frameworks.

The recommended loader deliberately retains `NSDocumentController`'s coordinated reading and document registry: acquire with `super.openDocument(withContentsOf:display:false:completionHandler:)`, then render and attach only the requested destination window. Never use `display:true`, `showWindows()` or focus-existing as the replacement implementation. The public completion method can be wrapped in the app's async API; its completion must be called exactly once on the main actor.

## Acquisition, render and commit

1. **Capture destination synchronously.** A reader link or window drop captures that reader's ID. A File Open action captures the key reader, otherwise the main reader, **before the NSOpenPanel becomes key**. A Dock/Finder/Open Recent event captures the active reader at receipt. Do not query `NSApp.keyWindow` after asynchronous work and accidentally choose a panel or a different window. A native drop on a non-key reader should activate/target the receiving reader, never some other window.
2. **Assign request token.** Each window has a monotonically increasing generation. Newer opening intent invalidates previous pending replacement for that destination only. Panel cancellation changes no committed state and clears only that panel/request, not a newer one. Closing a captured reader cancels its request: no fallback into another window and no surprise new window. An explicit Command-N request is a separate not-yet-visible destination reservation and must not replace the origin reader.
3. **Preflight and acquire without display.** Require a file URL, inspect regular-file/directory/access and executable disposition, then acquire the native Markdown document through the superclass's coordinated read with `display:false`. Real open errors remain authoritative; special files must not be read as data after a racy probe. A read override should validate the opened object (regular file, nonblocking safe open/fstat where necessary) instead of trusting an earlier `stat` if it directly opens the URL. No POSIX mode/ACL/quarantine changes. Off-main read/decode work returns immutable text, not SwiftUI or AppKit views.
4. **Stage rendering separately.** Call the unchanged `MarkdownBlockRenderer.render(from:documentURL:)` off-main with the destination URL and the successfully decoded text. `MarkdownRenderDocument` is already immutable/Sendable. Rendering is currently nonthrowing/best-effort; do not invent a binary rejection policy or classify all empty renderings as failure. Test injected loader/render failures later to verify transaction behavior. Do not clear the old image store, navigation bridge, scroll anchor, focus, selection, URL, title or reader while waiting. Target remote images are not a prerequisite and do not delay commit.
5. **Commit on main actor, with no suspension.** Recheck live destination and latest generation after every await and immediately before commit. Keep the original NSWindow/NSWindowController identity, frame, full-screen and placement. Call `targetDocument.addWindowController(existingController)` (the API removes it from the prior document), install the prepared reader input and synchronize title/represented URL within that single main-actor commit. This is real native document rebinding, not only a title change. For a new/zero-window destination, allocate and show a reader only after preparation succeeds. Request tokens prevent two cold opens from independently creating windows.
6. **Only successful commit resets the reader generation.** Host a reader subtree keyed by committed presentation ID, so old image tasks/traversal/resize work are canceled on retirement and new per-document state starts coherently without an initial blank render task. Keep the same native window. A failure never replaces the subtree, preserving old selection/scroll/focus and already-decoded images. Keep resize/restoration code intact rather than fixing #38 here.
7. **Release native identities correctly.** `NSDocumentController` owns documents; documents own attached window controllers; the coordinator owns live window destinations. When transferring the last controller away, close the old document only if it has neither other windows nor a pending acquisition reservation. Never call `oldDocument.close()` while another viewer remains. Superclass acquisition can deduplicate simultaneous opens; track pending consumers so a canceled request cannot close another request's candidate. Release abandoned, windowless candidates after all interested requests finish. Superclass-coordinated opens/`NSDocument.close` balance file-presenter registration; do not add a second presenter or implement automatic refresh (#23).

### Already-open targets, identity and fragments

- Another window already showing B does **not** redirect an A-to-B replacement into B's window. Attach A's existing controller to B's native document as an additional viewer. Other viewers and their reading positions remain untouched. This follows the approved active-window requirement; no old focus-existing exception remains for these routes.
- Use canonical standardized/symlink-resolved URL **for native acquisition identity**, while keeping each window's requested/opened URL as its displayed/location/path-resolution base. Render using that same per-window opened URL. A canonical identity key must not rewrite leading-slash or relative-path semantics. Override title synchronization, when necessary, to use that committed per-window URL; `NSDocument.fileURL` still identifies the same underlying file, never the previous one. Keep File > Reveal in Finder and the represented URL aligned with the committed input. This also distinguishes equal basenames in different directories.
- Reusing an already-open native document can reuse its last successfully decoded text, as the existing native reopen behavior does. Still check current target access/missing state. This does not promise external-update refresh; #23 remains out of scope. Per-window render/input is independent even if immutable text is shared.
- Replace `sectionRequests: [URL: SectionRequest]` with a one-shot `(windowID, committedPresentationID, requestSerial, fragment)` command delivered only to the winning reader. No-fragment request clears pending fragments for that destination only. Obsolete/canceled completions cannot clear newer requests.
- On a new successful document presentation, a supplied fragment resolves using the **new** anchors, after the reader is attached. An absent anchor reports the existing missing-section message in the successfully opened target; it is not a file-read failure requiring rollback. Empty fragment goes to top. No fragment starts a different document at top.
- Pure `#fragment`/footnotes stay in the current reader. A path-bearing self-link to the same opened URL uses current content/position if no fragment; with a fragment it navigates that reader. Command-click is identical. Do not rebuild the same reader merely to focus it. A newer same-document fragment action must also supersede an older pending file replacement so a late read cannot jump away unexpectedly.
- Preserve `DocumentLocalPath.resolve`, exact-once decoding, current-folder leading slash, `../`, spaces, Unicode, query treatment and first-wins/case fallback anchors. No repo discovery, grant-root restriction or new Markdown syntax.

## Native shell and lifecycle

### Public AppKit integration

- Programmatic `NSApplication` main with a strongly held delegate; create custom document controller before `shared` can instantiate the default. Existing SwiftUI blocks continue in `NSHostingController`. No empty SwiftUI scene or hidden DocumentGroup is retained to manufacture menus.
- Override `NSDocumentController.openDocument(_:)` for Command-O and call its standard `beginOpenPanel(completionHandler:)` flow, customizing the panel through `beginOpenPanel(_:forTypes:completionHandler:)`. Capture intent/destination before starting it. Use claimed Markdown types and no directory selection; native picker is a document selector, **not a permission-setup panel**.
- Override `newDocument(_:)` as File > New Window / Command-N with a separate new-window intent. Do not call `super.newDocument`, create an editable untitled document, use Duplicate, or save a temporary copy. Native automatic tabbing is disabled for these reader windows so Command-N means a separate window; do not expose independent New Tab/new-view actions that bypass policy.
- Override the public URL open entry point so standard native opens go through the same route. Its acquisition helper calls **super**, not the override recursively, with display false. Preserve main-thread completion and `documentWasAlreadyOpen` meaning. Do not let AppKit's default `display:true` focus/all-windows path run behind the coordinator.
- Finder/Open With/double-click/Dock dropped files: handle the native document file event once. For a batch use `application(_:openFiles:)` and `reply(toOpenOrPrint:)` once after the outcome, not success at dispatch. Do not also install `application(_:open:)` expecting it to receive Markdown files: Apple's documented URL delegate method excludes files with an associated NSDocument class and suppresses the older file delegates. Keep the controller URL override as the standard document-system entry point too; do not dispatch both paths for one event. File-event/launch arbitration is an explicit later native-validation risk, not evidence claimed from code reading.
- Startup without a file uses AppKit's untitled-open query, not an unconditional `applicationDidFinishLaunching` timer: in `applicationShouldOpenUntitledFile`, consume a once-only initial no-file request, schedule the native document panel via the coordinator and return false to suppress untitled creation. Explicit file intent marks/cancels any pending startup picker request before it presents. Do not return a fictional successful untitled document from `applicationOpenUntitledFile`. No startup retry loop after cancellation or file failure.
- Last close only unregisters/cancels that destination. `applicationShouldTerminateAfterLastWindowClosed` remains false; close does not ask for a new picker. Dock reactivation without files may raise existing/minimized readers but should not manufacture a reader or setup UI when there are none (recommended quiet default, P2 never required a new Dock policy). Quit marks terminating and cancels all pending panels/tasks; no late completion reopens UI.
- Ordinary Close/Command-W uses `NSWindow.performClose` through the responder chain. Window close bookkeeping comes from native close notifications/delegate, not `DocumentReaderView.onDisappear`. Keep native traffic lights/full-screen, size 900×720 and minimum 480×320, adaptive appearance and no toolbar.
- Native Open Recent remains backed by `NSDocumentController.noteNewRecentDocumentURL`, `recentDocumentURLs` and `clearRecentDocuments`, not new bookmark/history persistence. Prefer AppKit's standard Open Recent menu; if the programmatic shell requires explicit menu population, use those public APIs and NSMenu delegates/actions, **not private recent-menu selectors or identifiers**. Only successfully committed documents enter recent history; where superclass acquisition would note a candidate early, defer that notification until commit. Recent selection has ordinary replacement intent. No scroll restoration across launches (#24), file refresh (#23), autosaved reader-session reconstruction or saved-state migration is added. Do not erase old user saved state/preferences.

### Final defaults approved by the user

The following research discussion is retained as history; both recommended defaults are now binding under the approval linked above.

**D1 — No-reader and Command-N setup (approved; historical rationale).** Zero-reader Open/Finder/single-file drop creates the first reader only after success; this is the already-approved P2 exception, not a request for an additional window. Command-N shows a native single-file picker for a new reader, creates that reader on success and changes no existing window on cancel/failure. It never displays a blank editor/starter window. This is the smallest interpretation consistent with P1/P2 and read-only use. Ask for confirmation with D2 rather than treating a blank Command-N scene as authorized.

**D2 — Batch requests (approved recommendation; historical alternatives).** Recommend single selection in Open/New pickers and reject a Finder/Dock/window-drop request containing more than one supported Markdown file with: “Open one Markdown file at a time. Use Command-N for another window.” Keep current content and open no extra windows. Filter unsupported window-drop items as today, then count supported Markdown candidates. Do not silently ignore files or churn through a sequence where only the last one remains visible. Alternative, if the user prefers it: process in supplied order in the one captured destination, making the last successful file visible and reporting failures. The old distinct-windows-per-file behavior conflicts with the new intent and must not be retained as a hidden exception.

**Concise coordinator question:** “For Command-N, may NeoMD show the native file picker and create the additional reader only after a successful choice (Cancel changes nothing)? For several files dropped/opened together, should it ask for one file at a time rather than silently showing only the last file?” The recommended yes/yes policy makes the implementation scope fully determinate. No need to ask again about Markdown-only, Command-click, sandbox removal or bookmarks.

## Read-only and security removal

Removing sandbox removes an OS-enforced read-only boundary; application code must still be read-only. Use no saving, autosaving, duplicate/export, rename/move, lock/unlock (these mutate metadata), or write-producing titlebar actions. The NSDocument subclass must reject writable representations and write entry points before any superclass filesystem work; disable mutation command validation and guard direct move/lock/unlock APIs, not just hide menu items. Do not call `updateChangeCount(.changeDone)`; loaded documents stay unedited, autosaves-in-place/drafts and version preservation are off, Close/Quit have nothing to save. Keep native text noneditable and checkboxes noninteractive. Native title location/reveal remains available without file mutation. Later units must invoke the actual rejected write/metadata paths, not merely inspect the error enum.

Remove these exact access consumers:

- `DocumentOpeningCoordinator.folderAccess` and `applicationWillTerminate` grant cleanup.
- `DocumentReaderView.openLocalTarget` inaccessible → `requestReadAccess` branch, plus `.environment(\.documentImageAccess, ...)` and shared retry callback.
- `MarkdownImageParagraph.requestAccess`, `accessIsFocused`, `requestFolderAccess`, the Allow button/keyboard action/accessibility hint and `EnvironmentValues.documentImageAccess` definition.
- Delete `FolderAccessSession` itself, its directory panel, lease array and start/stop balancing. There is no persisted state to migrate.
- Drop modifier's sandbox-extension loop is no longer the app's authorization mechanism. Perform ordinary reads; remaining OS failure must not be conflated with absent security scope.
- Update `LocalFileAccessTests.folderSuggestionFallsBackToDocumentFolder` and `MarkdownImageHostingTests`'s injected access environment only after implementation is authorized. Retire that obsolete folder-policy test rather than inventing replacement grant logic.

**Proposed copy/retry detail, not new setup:** Document notice/native open error: “Couldn't read ‘name’. Check the file's permissions in Finder and NeoMD's access in System Settings > Privacy & Security, then try opening it again.” Missing file: give the requested path/location and ask to check whether it moved or the volume is connected. Decode/open errors use concise known failure text and a readable path, not raw Cocoa implementation detail. Don't diagnose every EPERM/EACCES as TCC or instruct everyone to grant Full Disk Access. No attempt to change TCC or permissions in-app.

For an inaccessible local image keep alt text/quiet unavailable status, show the corresponding concise access direction, and replace Allow with **Retry image** that only retries the loader (the existing `retryInaccessible()` is sufficient for the current image store). No permission picker, folder-selection promise, automatic retry loop or network blocking. Retry can become useful after the user changes OS access separately. Keep the current image treatment/colors/network policy; this necessary consumer cleanup is not a new image feature story.

Local-dispatch safety needs a final scoped audit because `.external` currently hands explicit `file:` URLs straight to the system action. Preserve the resolver's distinction (do not reinterpret absolute `file:` URLs as document-relative paths), but apply the approved application/executable reveal-only guard to **all file URLs before external dispatch** as well. Scheme-bearing web/custom explicit links keep their existing policy. Check the actual resolved target's application/executable metadata, including symlinks; extension alone is not sufficient. Failed/uncertain classification must not launch the target. Do not add `Process`, shell execution, executable fixtures or arbitrary custom URL automatic activation. A script/document handler's effects in another app are not proof NeoMD itself wrote or executed source; never claim global immutability of third-party apps.
